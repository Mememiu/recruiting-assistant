# Design System: 招聘工作台

## Overview

本文件记录 2026-09-23 已实现的未读待办界面，供后续维护保持一致。沿用工作台的浅色背景、紫色操作强调、白色容器和紧凑信息密度；既有台账、候选人档案和任务入口保持原有用途。操作流程见根目录 README，本文件不重复业务规则。

实现依据为 `public/css/style.css`、`public/css/inbox.css`、`public/index.html` 和 `public/js/app.js`。`design-system.md` 是既有风格参考，其中推荐字体等描述与运行代码有差异时，以实际样式为准。

## Colors

沿用 CSS 变量：页面背景 `--gray-50`，主文字 `--gray-800`，辅助文字 `--gray-600`，分隔线 `--gray-200`。紫色主按钮和选中态延续既有主色系；未读入口及选中行使用 `--primary-50`，选中行另有 `--primary-300` 内边框。待整理批次使用浅黄色提示；失败提示使用深红色并附具体文字。

## Typography

使用系统无衬线字体栈，优先苹方或微软雅黑，无新增在线字体依赖。待办标题（23px、600）、候选人标题（21px）、列表姓名（15px）、正文与沟通内容（14px）、元信息（12–13px）形成阅读层级。沟通正文保留换行、允许长文本换行，行高为 1.8；列表摘要限制两行。数量使用等宽数字。

## Layout

保留顶部页签和概览页入口。待办页由标题与拉取按钮、状态提示、按需出现的批次整理条、进度与搜索筛选、列表与详情组成。

桌面使用两列：左侧列表宽 260–340px，右侧详情占剩余空间，间距 24px。列表最大高度 70vh，完整沟通最大高度 420px，分别支持滚动。详情按姓名及关联信息、摘要、下一步、查看操作、完整沟通、跟进表单排列；已有判断和跟进历史折叠展示。

屏宽不大于 760px 时变为上下单列，间距 16px，列表最大高度 310px，详情内边距从 24px 减为 18px。标题、入口和整理条纵向排列，页签可横向滚动；同一断点同时收起顶部副标题，将图表改为单列。

## Elevation & Depth

既有概览和图表保留轻阴影。待办列表与详情使用白底、细边框和平面分隔；选中项通过浅紫底和内边框区分，悬停通过浅灰底提示。

## Shapes

入口、整理条、列表及详情使用 12px 圆角；沟通内容底板和文本框使用 8px 圆角。操作按钮沿用既有组件，按需换行。文本框占满详情宽度，最小高度 96px，可纵向调整大小。

## Components

- **列表与筛选**：提供待处理、全部、已处理，以及姓名、岗位或消息搜索。行内显示姓名、岗位、时间、摘要和文字状态；当前选中项不在筛选结果中时选择首项，无结果时显示恢复操作提示。
- **加载与异常**：概览入口有读取中提示；状态区展示最近抓取、无记录、整理结果或失败原因。未整理批次可预览，读取沟通与保存操作禁用并说明原因。关联冲突直接显示；无法安全读取沟通时禁用该操作。
- **跟进表单**：保存记录可继续保留待办，也可标记已处理；已处理条目可重新加入待办。空记录给出校验提示。草稿按待办 ID 保存于内存和浏览器会话存储，切换候选人、筛选或重绘时恢复；保存成功才清除对应草稿，失败时保留。会话存储不可用时退回内存，不承诺跨浏览器会话保存。
- **可访问性**：列表行使用原生按钮和 `aria-pressed` 表示选择；筛选与记录输入有标签；状态与详情使用礼貌播报区域。待办范围内键盘焦点有 2px 紫色外框及 3px 偏移。禁用态同时使用原生禁用和视觉弱化。系统要求减少动态效果时关闭视图入场动画。

## Do's and Don'ts

- **Do** 保留摘要、完整沟通、历史记录的层级，以及每项操作的明确中文含义。
- **Do** 保持待办完成状态与候选人筛选状态分离；关联台账显示唯一序号，编辑继续按稳定行 ID 定位。
- **Don't** 将本地跟进表单变为自动对外发消息入口；保存跟进不会发送消息或自动改变筛选结论。
- **Don't** 因 BOSS 消息变为已读就隐藏本地未完成待办，或在刷新详情时丢弃尚未保存的草稿。
