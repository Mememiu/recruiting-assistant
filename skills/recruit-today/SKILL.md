# recruit-today —— 招聘驾驶舱（只读状态扫描）

每天打开工作区的第一站。它回答两个问题：**现在进行到哪了**、**今天该干什么**。

## 它做什么 / 不做什么

- **做**：读事实源 → 算数字 → 按优先级排出一张决策卡，每条建议配一句可直接复制的话
- **不做**：不打招呼、不改台账、不拉未读、不调 AI —— 一个动作都不执行
- 为什么这样分：动作一旦执行就不可逆或有消耗，必须走各自的安全确认流程（票据/授权）；
  驾驶舱只负责让你**在 5 秒内知道该点哪里**

## 执行方式

```bash
node skills/recruit-today/scripts/today-scan.js [工作区路径]
```

（不带参数默认当前目录。找不到共享实现时脚本会提示，通常是工作区没初始化或 workbench/ 被挪走了。）

脚本读这些事实源（全部只读）：

| 事实源 | 取什么 |
|---|---|
| `CONTEXT.md` 四、在招岗位与优先级 | 哪些岗在招、优先级、是否「待梳理」 |
| `02-sourcing/dedup-ledger.csv` | 各岗待初筛/待过硬门槛/已过初筛/已打招呼人数 |
| `runtime/inbox.json` | 未读待办人数（按岗位分组，已处理的不计） |
| `01-jd/_internal/<role>.md` 关键词迭代表 | 最近一轮的有效/无效搜索词（搜够 3 轮提示做市场盘点） |

## 决策卡的优先级逻辑

按「不花钱的优先、时间敏感的优先」排：

1. **未读待办** —— 趁热聊转化率最高，且读沟通免费
2. **标准未梳理的岗** —— 排在高位因为**没有标准就没法初筛**，先把根问题解决
3. **未过硬门槛的人** —— 批量硬门槛筛选免费（`boss chat` 不花额度），先筛掉不合规的
4. **待初筛的人** —— 命脉判断在打招呼之前做完，别浪费畅聊卡
5. **已过初筛但没打招呼** —— ⚠️ 会消耗平台额度，标出来让你自己决定
6. **搜了 3 轮还没结果** —— 提示做一次市场盘点（标准或渠道可能该调）
7. **跟进已打招呼未回复的**、**收工出日报**

## 用户说「按推荐来」时

从上往下按**免费动作**依次做（跳过消耗额度的打招呼，或做到那步停下来问）。
每完成一步可以重跑一次扫描——数字会变，决策卡自动更新。这比一次性扎进 daily 流水线
更可控：你随时知道自己在哪、还剩什么。

## 输出纪律

- 数字全部本地算，不许估；台账里没有的口径就不显示
- 「台账有某岗的人但 CONTEXT 没登记」要警告 —— 这种状态分裂会让路由漏掉这个岗
- 决策卡是**建议**不是指令：用户完全可以无视它直接说要做别的，别拦着
